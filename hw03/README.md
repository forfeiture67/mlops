# ДЗ 3. Git LFS и DVC

`make_lfs_files.py` генерирует два одинаковых файла по 2 MiB. Один хранится обычным
Git, второй — LFS. Сравнение двух версий файлов выполняется в том же репозитории;
новые репозитории создавать не нужно. Последовательность — в GUIDE_WINDOWS.md.

DVC-проект расположен в этой папке и инициализирован с `dvc init --subdir`.
`data/raw.csv.dvc` описывает исходные данные, `dvc.yaml` — зависимости стадий,
`dvc.lock` фиксирует реальные контрольные суммы данных, кода и параметров.

| Стадия | Действие | Выход |
|---|---|---|
| prepare | Удаляет неполные строки и фильтрует x по min_x | clean.csv |
| split | Перемешивает с фиксированным seed, делит 80/20 | train.csv, test.csv |
| train | Вычисляет коэффициенты линейной регрессии МНК | artifacts/model.json |
| evaluate | Оценивает модель на test | metrics.json: MAE, RMSE, R² |

Создаются 120 синтетических наблюдений y = 2.5x + 7 + шум и одна неполная строка.
Код стадий использует стандартную библиотеку Python. Генератор намеренно не
входит в DAG: исходный файл версионируется через `dvc add`, как внешние данные.

Remote `local` указывает на папку `mlops-dvc-storage` рядом с Git-репозиторием.
DVC сохраняет относительный путь относительно своего config; поэтому внутри
`.dvc/config` видны три перехода вверх, а команда настройки из hw03 использует два.
Это папка на диске, не облако: преподавателю для `dvc pull` потребуется доступ
к ней или собственное воспроизведение данных по генератору.

На новом компьютере из hw03: `python -m pipeline.make_data`, `dvc add data/raw.csv`,
`dvc repro --force`, `dvc push`. Это создаст собственные кэш и remote.
Существующие `.dvc`, config и lock из архива сохраняются; повторный `dvc init` не нужен.

Проверенные метрики и сценарии восстановления перечислены в `../VERIFICATION.md`.
